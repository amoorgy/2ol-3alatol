# Cohere-Track Mini-Experiments: Orthographic Robustness of Egyptian Arabizi

- **Date:** 2026-08-20
- **Status:** design approved in chat; awaiting spec review
- **External deliverable:** email to Marzieh Fadaee (Head of Cohere Labs), target Mon 2026-08-24 / Tue 2026-08-25
- **Track name:** `d5_cohere_track`

## 1. Motivation and framing

Egyptian Franco-Arabic (Arabizi) has no standard orthography. The same word is
written many ways (`gedan`/`gdn`, `a5sam`/`akhsam`, `3ayez`/`aayez`/`ayez`).
This track asks three questions, each anchored to a published Cohere Labs
technique, and then connects them:

1. **Do tokenizers see these spellings as the same word?**
   (One Tokenizer To Rule Them All, arXiv:2506.10766 — Fadaee co-author)
2. **Is there a measurable *script* gap in comprehension, separable from the
   cultural-knowledge gap?**
   (Global MMLU, ACL 2024 — Fadaee co-author)
3. **Does re-authoring prompts in-language, rather than translating them, fix
   script-breaking in generation?**
   (The Art of Asking, arXiv:2510.19806 — Cohere Labs)

The original contribution is not any single replication. It is (a) a two-sided
robustness metric that separates under-robustness from over-robustness, (b) the
observation that Global MMLU's culturally-sensitive/agnostic decomposition
assumes one orthography per language and therefore needs a third axis for
dialects that have none, and (c) a provenance finding: the Arabizi in NileChat
was generated by Cohere's own `c4ai-command-r-plus-08-2024`, so its spelling
distribution is a model's habits rather than a population's.

### Honest scope limits, to be stated in the writeup

- We cannot replicate the *downstream* claim of One Tokenizer To Rule Them All
  (win rates after language adaptation) because that requires pretraining. We
  test the tokenizer-level mechanism the claim rests on.
- Global MMLU used human annotators for culture-sensitivity labels. We use a
  subject-level prior plus an LLM vote, and label it as a proxy.
- Frontier models accessed by API expose no logprobs, so their multiple-choice
  scoring is not method-identical to local log-likelihood scoring.

## 5. E1 — Variant probe: tokenization and comprehension

### 5.1 Phenomenon taxonomy

Digit substitutions, ordered by the ambiguity of the Latin form:

| Class | Digit | Arabic | Latin form | Pre-images of the Latin form | Reversible |
|---|---|---|---|---|---|
| `DIGIT_SAFE` | `5` | خ | `kh` | خ | yes |
| `DIGIT_SAFE` | `8` | غ | `gh` | غ | yes |
| `DIGIT_RARE` | `4` | ش | `sh` | ش | yes, but `4` is rare in Egyptian usage |
| `DIGIT_AMBIG` | `7` | ح | `h` | ح, ه | no |
| `DIGIT_AMBIG` | `3` | ع | `a`, `aa`, ∅ | ع, ا, أ, short vowel | no |
| `DIGIT_AMBIG` | `2` | ء, ق | ∅, `a`, `o`, `u` | hamza, Cairene ق | no |

Open for native review: whether `6` (ط) and `9` (ص) are attested often enough
in Egyptian Arabizi to include. Working assumption: rare, excluded from the
first pass, recorded if the miner surfaces them.

Non-digit classes:

| Class | Example | Description |
|---|---|---|
| `VOWEL_DROP` | `gedan` / `gdn` | most short vowels removed |
| `VOWEL_DROP_MED` | `benhawel` / `benhawl` | single medial vowel removed |
| `VOWEL_LENGTH` | `aayez` / `ayez` | doubled vs single vowel |
| `FINAL_Y_I` | `walahy` / `walahi` | word-final `y` vs `i` |
| `INITIAL_HAMZA` | `akhsam` / `2akhsam` | word-initial hamza written or not |
| `COMPOUND` | `ba3atelak` / `baatelk` | two or more classes fire on one edge |

### 5.2 Rule asymmetry and licensing

The central linguistic constraint: **digit to Latin is sound-preserving;
Latin to digit is not.** `a5sam -> akhsam` is always licensed. `ahsan ->
a7san` is licensed only because that `h` realises ح; applying the same rule to
`hena` (هنا) yields `7ena`, which is not Egyptian Arabizi.

Therefore a rule application is **licensed** only when the Arabic pre-image
matches. Every probe cluster carries its Arabic form, which is what makes
licensing decidable. Unlicensed applications are generated deliberately as
illegal variants (section 5.6).

### 5.3 Probe set construction

Target 40-60 clusters. Three sources, all provenance-labelled:

1. `hand` — clusters authored by the native-speaker author (approx. 10 exist
   already from the design conversation).
2. `mined_nilechat` — candidates mined from `UBC-NLP/nilechat-arabizi-egy`
   (572k rows, parquet, CC-BY-NC-4.0) using `src/franco/skeleton.py` as the
   collision key.
3. `mined_attested` — the existing 60 clusters in
   `data/benchmark/variant_clusters.tsv`, mined from real human text.

Candidates are auto-classified per edge by `phenomena.py`, written to a TSV
review file, and **manually accepted, corrected, or deleted by the author**.
Only reviewed rows enter the frozen probe set. The review step is a hard gate,
not advisory.

Frozen record shape:

```json
{ "cluster_id": "akhsam",
  "arabic": "أخصام",
  "meaning_en": "enemies, adversaries",
  "meaning_ar_accept": ["أخصام", "أعداء"],
  "register": "colloquial",
  "source": "hand",
  "variants": ["akhsam", "a5sam", "2akhsam", "2a5sam"],
  "edges": [
    {"a": "akhsam", "b": "a5sam",  "classes": ["DIGIT_SAFE"], "n_edits": 1},
    {"a": "akhsam", "b": "2a5sam", "classes": ["DIGIT_SAFE", "INITIAL_HAMZA"], "n_edits": 2}
  ],
  "illegal_variants": [] }
```

**Hard negatives are required.** The set must contain minimal pairs that look
similar but are different words (for example `2alb` قلب heart vs `kalb` كلب
dog). Without them, a model that answers "same word" to everything scores
perfectly and the metric measures nothing. Target at least 10 hard negatives.

### 5.4 Layer A — tokenizer fragmentation

No inference. Per edge, per tokenizer:

- `same_seq` — token ID sequences identical
- `len_delta` — absolute difference in token count
- `jaccard` — over token ID sets
- `frag` = `1 - jaccard`

Aggregated as **phenomenon class x tokenizer**.

Note that **linguistic safety and tokenizer safety are orthogonal**, and the
class names refer only to the former. `DIGIT_SAFE` means the substitution is
reversible without knowing the Arabic pre-image; it says nothing about
tokenization. The prediction to test is in fact that `DIGIT_SAFE` edges fragment
*worst* among single-edit classes, because `5` is a numeric token while `kh`
merges into existing Latin subwords, so the two spellings share no surface at
all. `FINAL_Y_I` should fragment least. If that prediction holds, the mappings
easiest for a human to reverse are the hardest for a tokenizer to unify, which
is a result in its own right.

Tokenizers: Aya Expanse, Command R7B Arabic, NileChat-3B, Qwen3, Gemma 3,
Llama 3.1, ByT5 (byte-level control), `o200k_base` (frontier reference).

### 5.5 Layer B — comprehension

**Meaning probe**, temperature 0, one call per variant per model:

> What does this Egyptian word mean? Answer with one Arabic word only: `{variant}`

Scoring against `meaning_ar_accept` after Arabic normalisation (strip diacritics,
unify alef/hamza forms, unify ta-marbuta/ha).

**Validity control (mandatory).** Each cluster is also probed in its Arabic
script form. A model that cannot meaning `أخصام` correctly has no business being
scored on `a5sam`, and its Arabizi numbers are reported as invalid rather than
as failure. This prevents attributing general incapacity to orthography.

Per-edge outcome buckets: `both_correct`, `flip` (one spelling correct, the
other not), `both_wrong`.

Headline metric: **spelling-induced comprehension flip rate**, per phenomenon
class, per model.

Cluster-level: reuse `src/franco/metrics.py` C@k for self-consistency — do all
*k* variants of a cluster receive the same meaning, correct or not. Report
consistency and correctness as a 2x2, because a model can be consistently
wrong, which is a different failure from being unstable.

Supporting probe: embedding cosine within-cluster versus across-cluster (Ollama
`/api/embed`), reported as separation. Evidence about representation, not
comprehension; it supports the meaning result and does not stand alone.

### 5.6 Over-robustness versus under-robustness

Illegal variants are generated by applying reverse digit rules where the Arabic
pre-image does not license them (`hena` -> `7ena`, and `a -> 3` where the letter
is not ع). These are then put through the same meaning probe.

- **under_robust_rate** — fraction of *legal* edges that flip
- **over_norm_rate** — fraction of *illegal* variants given the legal
  word's meaning

Reported as a two-dimensional scatter, never collapsed into one score. A model
that normalises aggressively can score perfectly on under-robustness while
having lost the ح/ه distinction entirely; measuring one side alone lets that
model look good.

### 5.7 Empirical mapping ambiguity

`nilechat-arabizi-egy` is a transliteration of portions of fineweb-edu-Egypt
and LHV-Egypt. **First implementation step is to inspect the parquet schema.**
If a source-text column survives, the corpus provides parallel Arabic/Arabizi at
scale, and the pre-image distribution of each Latin form (`h`, `a`, `kh`, `gh`,
`sh`) can be counted rather than asserted. That yields confidence-weighted
mappings, and gives `src/franco/taxonomy.py` data-derived priors for the author
to sign off on under rule #3, instead of hand-invented weights.

If no source column exists, fall back to the author's judgment and record that
the weights are unvalidated.

### 5.9 Provenance analysis

Same metrics on two corpora: Command-R+-generated Arabizi
(`nilechat-arabizi-egy`) versus real human Arabizi (`data/seed/*.jsonl` plus
`data/interim/clean_franco_records.jsonl`).

- digit-letter rate per 1,000 characters, broken out per digit
- vowel-drop rate
- **spelling entropy per word type** — how many distinct spellings one word
  actually receives

Hypothesis to test, not assume: Command R+ produces lower spelling entropy than
human writers, meaning models pretrained on this corpus see a sanitised
Arabizi. A null result here is equally reportable.

## 6. E2 — Global MMLU with a script axis

- `UBC-NLP/EgyMMLU`: 22,027 multiple-choice questions, 44 subjects, Arabic
  script, schema `question / choices / answer / subject`. Sample 600 from the
  **test** split, stratified by subject, seed 13. The remainder is never
  inspected.
- Two renderings per item: original Arabic script, and Arabizi produced by LLM
  transliteration. Arabic-to-Arabizi is **not** a deterministic mapping, because
  Arabic script omits short vowels and Arabizi writes them; an LLM performs the
  base rendering and the author validates a 50-item sample by hand.
- Culture-sensitivity labels: subject-level prior plus a three-vote LLM pass on
  ambiguous subjects. Labelled as a proxy for Global MMLU's human annotation.
- Scoring: length-normalised log-likelihood over the four choices for local
  models; constrained A/B/C/D letter output for API models, with the asymmetry
  stated.
- Output: accuracy over **script x culture-sensitivity x model**.

The claim being extended: Global MMLU separates capability from cultural
knowledge but implicitly assumes one orthography per language. Egyptian Arabizi
has none, so the decomposition needs a third axis.

## 7. E3 — The Art of Asking

150 real Arabizi first turns drawn from `data/seed/` — this arm uses **only
human-authored text**.

Instruction conditions, cumulative, following the paper's three transformations:

| Condition | Description |
|---|---|
| `C0` | English instruction |
| `C1` | MSA Arabic instruction (the paper's translation baseline) |
| `C2` | `C1` + Naturalness — re-authored in Arabizi, not translated |
| `C3` | `C2` + Cultural Adaptation |
| `C4` | `C3` + Difficulty Enhancement |

Scoring is fully objective; **no LLM judge in this pass**:

- Latin versus Arabic character ratio
- **script-break rate** — responses with more than 20% Arabic-script characters
- **wrong-language rate** — language ID returns neither Arabic nor Egyptian
  Arabizi (this quantifies the Turkish-reply anecdote directly)
- Arabizi-marker density — use of `2 3 4 5 7 8`

## 8. E4 — Correlation, with the null pre-registered

Per-item join of Layer A fragmentation (under each model's own tokenizer)
against three outcome variables. Because per-item accuracy is binary, the E2
outcome is defined as a **flip bucket** in the same shape as E1, not a
continuous drop: for each item, `both_correct` / `flip` / `both_wrong` across
its Arabic-script and Arabizi renderings. The three outcomes are therefore:

| Outcome | Unit | Definition |
|---|---|---|
| E1 flip | probe edge | one spelling's meaning correct, the other not |
| E2 flip | EgyMMLU item | correct in one script, wrong in the other |
| E3 break | generation turn | more than 20% Arabic-script characters in the reply |

Spearman ρ with bootstrap confidence intervals, computed separately per outcome
and per model. Fragmentation is aggregated over the words of an item by mean,
with the max also reported, since one catastrophically fragmented word may
matter more than a mildly fragmented average.

**Committed in advance:** if ρ is indistinguishable from zero, that is the
reported finding — fragmentation does not explain the script gap — and no
further slicing is performed. This is recorded here, before any data is seen,
so that the analysis cannot be reshaped to find an effect.
